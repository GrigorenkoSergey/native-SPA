## [Результат экспериментов](https://grigorenkosergey.github.io/native-SPA/)

## Что это за репа?
Здесь попытка создать простенькое SPA приложение, удовлетворяющее следующим требованиям:
* Использования сторонних библиотек сокращено до минимума. Используем только сборщик (выбран webpack) и нативные возможности браузеров. Да и то, сборщик (как сторонняя технология) выбран исключительно для возможности дальнейшего подключения TS.
По факту можно было бы обойтись вообще без него, может быть было бы проще. Уж слишком много ньюнсов возникает с использованием сборщиков. 
* Cтраницы и стили подгружатся лениво (только по мере необходимости).

## Роутинг и менеджер состояния
Здесь создан свой собственный роутинг и менеджер состояний. 
Код каждой страницы должен храниться в директории pages.

Все, что должно храниться в памяти приложения, и быть доступным для всех страниц, храним в директории stores в отдельных файлах. 

## SEO
На каждой странице включено только то, что ей необходимо и в полном объеме. Сложные элементы будут генерироваться с помощью web-components, которые более-менее дружат с поисковыми роботами. Таким образом, SEO получаем из коробки. 

## Разработка
Уникальный код каждой страницы находится в соответствующей директории в папке pages в отдельной папке. В каждой такой папке должны быть файлы `index.html`, 
`index.js`, `style.css`. Можно создавать глубоко вложенные страницы, они будут также найдены и обработаны.
```
src/pages/
├── page-1
│   ├── index.html
│   ├── index.js
│   ├── page-1-deeper-page
│   │   ├── index.html
│   │   ├── index.js
│   │   └── style.css
│   └── style.css
├── page-2
│   ├── index.html
│   ├── index.js
│   └── style.css
└── page-404
    ├── index.html
    ├── index.js
    └── style.css
```

Во время сборки html-код страницы помещается в [шаблон](./src/page-template.html) (см. правило `test: /index\.html$/i`). Обратите внимание на относительные пути в шаблоне и тег `base`.

Далее вставляется общий код `main.js` в каждой странице (см. настройку `HtmlWebpackPlugin`). Там содержатся общий скрипт для всех страниц. В частности подключение роутинга и общие стили. Когда пользователь заходит на любую существующую страницу, скрипт применяется, и далее переходы по страницам будут в рамках текущей сессии, без полной перезагрузки страницы.
